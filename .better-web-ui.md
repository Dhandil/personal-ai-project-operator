# Personal AI Project Operator — Web UI Design Context

## Audience

This is a personal operations desk for one user who acts as the project owner. The user can oversee several projects and delegates bounded work to agents; the interface should make the next human decision obvious without feeling like an enterprise administration suite.

## Primary jobs

- Enter a project and start today's work from one clear place.
- Move through Idea → Discovery → Spec → planning without carrying context between chats.
- Review agent proposals, approve or return work, and understand what is happening now.
- Hand the next bounded task to an agent and see evidence, progress, and recovery choices.

## Tone and visual direction

Use a calm, utilitarian operations-desk aesthetic: restrained dark navy surfaces, warm readable text, muted teal for primary action, and amber only for human decisions or risk. Prefer strong typography, compact spacing, visible hierarchy, and progressive disclosure over decoration. Avoid neon glow, gradient-heavy cards, generic AI dashboard ornament, and dense nested card wallpaper.

## Information architecture

The left rail is the global navigation: 工作台, 项目, 执行, 治理, 系统. Each module exposes its own short second-level tab row in the page header. The workspace landing page is an entry point, not a duplicate project overview. The project page owns current-project selection and “启动今日工作”.

## Interaction principles

- The primary action for the current page is always visible in the first viewport on desktop.
- Desktop uses a fixed shell with local scrolling for dense lists; small screens may use natural vertical scrolling.
- Status labels are explicit words and never rely on color alone.
- A cancelled or blocked stage must explain what the user can do next; avoid dead-end cards.
- Dense details (guidance, historical evidence, long lists) use collapsible or locally scrollable regions.

## Technical constraints

Keep the existing React/Vite routes, API contracts, governance semantics, and accessibility behavior. This redesign is a presentation and interaction-hierarchy change; it must not bypass approval gates or turn candidate material into formal facts.
